const 修饰指针的写法

const 修饰 char （ * p 指向的内容）。指针本身可以修改指向别的地址。

const 紧贴变量，修饰指针变量本身。可以修改指针指向的内容。

两者都 const ，指针内容不能改，指向的内容也不能改。

输出指针

一般来说，cout 一个指针，会直接在控制台输出指针中存放的十六进制内存地址，但 char 不一样。
cout 对 char 有重载，会直接打印字符串【读到 /0（ascii值为0）之后结束】。

关于string

string 的 find / rfind 函数返回的是无符号整数（size_t）。string::npos 的本质：(size_t)-1，无符号下等价于一个非常大的正数，用 int 接收不安全。

直接用双引号括起来的字符串称为字符串字面量（字符串字面量永远保存在内存的只读区域内），当用 char 来接收字符串字面量时，必须写 const char （部分编译器只允许这样）

如果我想定义带换行的字符串，最简单是加 \n ，但也有另一方法（c++11）。
括号内敲的回车，会直接变成字符串内部的换行 \n

关于const和类

在类中，const修饰的变量不能被改变。
const修饰的变量不能在构造函数体内赋值，可以在初始化列表中初始化。

const对象不能调用非const成员函数
所以经常会出现两个一样的函数但一个有const一个没有const

const成员函数 保证函数内不会修改对象（不修改 当前调用的this 中的非mutable成员变量）或调用任何非const成员函数
const修饰的方法中，mutable修饰的成员数据可以发生改变。

关于delete

delete释放当前指针指向的堆内存，指针变量本身不会被删除；

关于初步优化vector

打比赛从没想过优化的事情
如果我们直接创建vector，vector的大小会被设为1，若后续pushback，vector会自己删掉当前内存，找到一个更大的地方创建内存并把东西复制过去。这样复制的操作其实可以被避免
平时一般是打括号加数字的，那种情况下会额外创建三个元素的vector，调用默认构造函数，仅仅分配内存的话使用reserve即可。

那么为什么上面是emplace_back呢，这和push_back是有区别的。emplace_back的作用是在vector的末尾，就地构造一个新元素，不会产生临时对象。直接在参数列表中填构造函数的参数列表即可

注意：是vertices.emplace_back(1,2,3);而不是vertices.emplace_back({4,5,6});

关于库

比较大且正规的做法是：
拿到第三方库完整源码.c /.cpp ，使用cmake配置自己指定编译选项，在本机编译生成二进制产物.lib/.a /.so /.dll ，再将这些二进制文件链接进项目。
也可以直接下载别人编译好的二进制文件进行链接
